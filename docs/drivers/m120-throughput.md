# 120 Hz composition throughput on piano

Goal 12 requires distinct desktop frames at the panel's cadence. The 2026-11-26 12:58 RAM run with `piano-dpu-modes=120` verified 119.990 Hz on both links at mode set and exposed only 3200×2136 at 120 Hz in CoreGraphics. During the probe, the desktop flipped at about 56 Hz. The scanout still refreshed the old surface on frames without a new flip.

## Capture and time base

The `v131y12p-m3-120` result has a GUI login, a completed 60 s load-0 capture, 3,386 display-link callbacks, 3,385 Metal submissions/completions and zero GPU errors. The app drawable was **2400×1424**. WindowServer handed the display a **3200×2136 '&BGA'** desktop surface. The probe received every presented handler but all 3,385 `presentedTime` values were zero, so the per-drawable presentation grade is VOID. The app's snapshot reads were denied. The separate root snapshots both succeeded and both INTF frame counters advanced by 8,962 ticks over 74.679211 s bracketing the probe (**120.007 Hz** on each link). The `COUNT_EN` readback was zero, so the current grader rejects these otherwise moving counters. M3 independently verified 119.990 Hz from counter motion at mode set.

Evidence comes from `console.out`, `m3-ft120.json`, the before/after snapshots and `m3-ft120-kernel.*`. Correlate `R3b DISPLAY at-us` with the adjacent NativeGopDisplay report and the app's monotonic window, 163.9365–223.9365 s. The five complete GOP windows inside that interval span 168.8219–218.8500 s. The opening report at 168.8219 s also contains pre-probe time. Some kernel log lines join mid-line, so match the driver prefix anywhere and require the expected fields. Across the five complete windows the GOP count rose from 1,963 to 4,763, or **55.97 accepted desktop flips/s**. GOP includes same-surface reshows. The last DPU rollup reports one reshow since boot, separately from its 2,858 new-surface flips. The tools observed neither per-drawable swap IDs nor individual latch times in this run.

The GPU reached the docked skin cap throughout the probe. Of 59 `R3b LV` rows inside the app window, 22 show level 13 at **1050 MHz** and 37 show level 12 at **967 MHz**, all with `bind=skinband`. At 186.73 s the skin reading reached the 45 °C boundary for level 12. Across those samples skin was 42.7–45.1 °C, XO was 50.2–54.9 °C and filtered SoC temperature was 83.8–90.6 °C. The SoC ladder was already at step 14 with `board-cap=0`. The binding cap is in `R3b LV` and `R3a RES ceiling`. The 222 MHz floor and higher allowed caps do not justify raising the floor in this capture.

## Ranked causes and next read list

1. **Serialized GPU readiness before flip.** The 10.93–11.35 ms fence observation and approximately 4–5 ms to latch/complete are on the same worker path. That path consumes two 120 Hz slots on average. Polled GPU job accounting and the global watermark leave true composition, unrelated work and observation delay confounded. The selected experiment tests observation delay while preserving the target sequence.
2. **Producer backpressure and the latch's phase.** The app spends a median 16.47 ms in one display-link invocation before commit. GOP reports Busy on the current swap, and a CTL flush that misses a scanout boundary can wait another period. The app's callback duration cannot be assigned to `nextDrawable` or to swap completion without correlated tracing. Early swap completion could recycle a still-scanned surface.
3. **Skin-limited GPU throughput.** The cap fell one level at 45 °C while the render server was busy. The reported level is already the maximum permitted by that band. A floor would not address the measured run.
4. **CPU clean/copy.** The M2 acquisition clean alone costs about 47% of one period when it occurs. This capture already skipped it in steady state and used address flips with zero copies. The legacy four-thread cost needs its own M2-off measurement.

3. Capture GOP fence wait, poll sleep count/time and late sleeps, submit → program, deferred time, flips/copies/Busy/drops and VBL counts. Pair with `R3b LV/WORK/RESF`, GPU IRQ status and DPU cadence/fault/underrun/clean counters. The signature for a poll delay is a fall in measured sleep and worker wait, followed by shorter deferred completion and higher distinct flip cadence. Steady fence wait despite punctual polls means queue/GPU work needs the next isolation step. Keep the app's raw callback and Metal times to catch backpressure and tail regressions.
4. If existing, collect a timestamped WindowServer GPU trace and CA readiness/dispatch observations. Include the ring sequence at program and at the first successful read. Record missing trace points explicitly. Zero `presentedTime` still requires the independent [presentation feedback investigation](presented-time.md). Qualify 120 Hz presentation only with a positive, distinct drawable series near 120 Hz with 8.33 ms intervals, tails and misses reported alongside hardware counters and new-flip cadence.

## Fix-image gate

Path: CA display link and Metal drawable → WindowServer composition → IOMFB selector 5 and NativeGopDisplay worker → A830 ring retire observation → PianoDpu clean/flush/VSYNC latch → gated completion and CA readiness/feedback. The reference and hop tables identify the checks and events.

Checks: ours-OK for the verified mode, M2 epoch, flip/latch and deferred completion. Ours-missing for swap-specific GPU attribution and absolute presentation feedback. Unknown for the GPU execution versus retire-observation split and the actual CA readiness branch.

Root cause: the captured serialized fence-plus-latch path is over budget before a swap completes. Its largest measured stage is GPU-fence observation. Polling overhead as a material contributor is a hypothesis. Goal 12 remains open.

ONE change: add a default-off, same-boot A/B for a 1 ms system-critical poll sleep with zero requested leeway on the verified M3 120 Hz flip path. Recheck the same fence and retain the hang guard and surface-ownership rules. Read per-arm poll timing and existing stage counters. This is an experiment for the selected bottleneck. Require a measured cadence improvement and all existing display and thermal checks before considering a production fix image or a default change.
