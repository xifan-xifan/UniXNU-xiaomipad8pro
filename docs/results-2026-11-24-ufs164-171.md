# ufs164-171: IOBlockStorageDriver 匹配与 UFS 容器 UUID

日期: 2026-11-24

范围: 仅 `fastboot boot` 临时镜像，未写分区、GPT、boot 镜像或 userdata。每轮由
`tooling/native/run-ufs16xtr.ps1` / `run-ufs171tr.ps1` 自动启动、抓串口、再回到
已完成启动的 HyperOS OS3.0.309.0.WPYCNXM A。

## 结论

- 手工 `new IOMedia` + `attach` + `registerService` 路线失败：父链
  (`IOMedia -> NativeUfsBlock -> NativeUfs -> K114cAP -> Root`) 正确、UUID 正确，
  但 `matched=0`，IOMedia 永不匹配（ufs160-165）。
- 异步 `registerService(kIOServiceAsynchronous)` 在早期不消费队列（ufs168/169）；
  `kernel_thread_start` 返回成功但派生线程不运行。
- ufs170/171 改为在发布线程内对 OS 窗口同步
  `device->startMatching(kIOServiceSynchronous)` 后，**IOBlockStorageDriver 首次
  真正匹配并回调**：`open`、`reportRemovability`、`reportMediaState`、
  `reportBlockSize`、`reportMaxValidBlock`、`reportWriteProtection` 全部进入。
- IOBlockStorageDriver 随后对该窗口发起真实读：block 0 count 1、block 1 count 1、
  block 0 count 3，OCS=0，说明 UFS 读路径可用。
- ufs171 从窗口首块读出 APFS 容器 UUID:
  - SystemOS = `79F45B3D-B2A6-4497-8467-1CFF475F2415`
  - OS = `A7672058-6BF2-44D4-AE1F-CBF9CF814C0D`
- 启动器等待的 `84581E99-85BE-4957-AC53-2947E887B3E4` 是 APFS 卷 UUID，
  不是容器 UUID，因此仍未匹配。
- 仍未出现 `IOMedia` 节点（`matched drivers = 0`），`startMatching` 未返回：
  IOBlockStorageDriver `start()` 内部阻塞，尚未发布媒体。
