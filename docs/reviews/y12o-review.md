## Findings

### P2 · TX restart can starve RX on the network thread

`package/PianoDwc3/PianoUsbNet.cpp:167–173,187–201,312–338` and `package/PianoDwc3/Dwc3Gadget.h:1192–1194`.

The same thread that dequeues incoming frames runs `oqService(fQueue, 0)` first and holds the controller work-loop gate during it. Apple's synchronous service may continue draining primary and shadow queues as long as TX makes progress and producers keep up. For example, after a stall on a fast USB link, a sustained small-frame sender can feed the family while USB removes records just quickly enough to avoid another stall. The network thread cannot deliver the host's frames during that drain. Once its RX ring reaches the OUT admission threshold, the gadget also stops posting further OUT requests. A down/up reset can start an inline drain too if producers enqueue between setting capacity and starting the family queue.

Commit `f9c84ab0` requests asynchronous family service for ordinary restarts and starts the empty queue before restoring its capacity. Reset and service are serialized by the controller work loop. Family calls run outside the byte-ring lock. The host test checks these call sites and the NCM model exercises saturation and reset. [Apple queue drain and restart implementation](https://github.com/apple-oss-distributions/IONetworkingFamily/blob/main/IOOutputQueue.cpp#L366-L597)

### P2 · A terminal trace sample delays the bonded recovery enable

`package/PianoDpu/DpuPanel.h:296–304`, `package/PianoDpu/DpuSlices.h:254–267`, `package/PianoDpu/DpuPanelTrace.h:67–86`.

If INTF2 stops and INTF1 refuses to stop, recovery waits for master lines 0–2 before enabling INTF2. The successful poll records a full trace row before returning. A poll near the end of line 2 can leave less time than the remaining MMIO reads, even with a sample shorter than one line. The subsequent enable then lands outside the start window. The existing trace test exercises one favorable polling phase.

Commit `29a9ce72` keeps recording while the alignment wait continues and on timeout. A successful wait records again after the enable store. The host replay forces a poll late in line 2 and checks the line at the actual store.

### P2 · The survey thread can observe partially read slice arguments

`package/PianoDpu/PianoDpu.cpp:592–599,689–698`, `package/PianoDpu/DpuSlices.cpp:105–109,154–166,1013–1029`.

`dpuSlicesWanted()` can initialize the global options from either the service start or the survey thread. The ready flag is written before the options. If the service start is descheduled after launching the survey, the survey can enter argument parsing first, and start can then see the early flag while the relevant options still hold their defaults. Start may skip launching the slice worker. If both readers pass the unsynchronized guard, the trace allocation added by `0ea7e24d` can also run twice. The panel worker itself is launched after slice start and owns all ring mutations.

Commit `61d7a0f8` initializes the slice arguments before publishing the survey thread and makes the query read-only. Allocation failure disables tracing alone. The startup test checks the call order used by the driver.

### P2 · The merged line can disagree with the kernel on duplicate boot arguments

`tooling/native/pianousb-shell/pianousb-shell.c:36–45`, `tooling/native/piano-usbnet-address/piano-usbnet-address.sh:26–31`, `package/PianoAuto/daemon/piano-rotated.m:90–121`, `tooling/native/piano-brightness-sync/piano-brightness-sync.m:60–82`.

XNU's ordinary named boot arguments take the last exact match. The C shell and rotation readers return the first one. The network address and brightness readers accept any enabling match. A hand-authored split can place `piano-usb-shell=0` in the base line and `piano-usb-shell=1` in the ADT tail. The kernel then creates the pipe and userland leaves its daemon inactive. A later `piano-rotate=0` can likewise leave the daemon acting on a stale enable. The space-only boundaries also miss arguments preceded by a tab in the loader portion, which XNU treats as a separator. The ESP editor already rejects duplicate names across the input split.

Commit `716fd73e` uses the last full key bounded by space or tab and evaluates that value once. The shell reader disables glob expansion during tokenization. Host cases cover both override orders, a tab separator, partial keys, a literal wildcard, and full-length and failed sysctl reads. [XNU named argument scanner](https://github.com/apple-oss-distributions/xnu/blob/main/pexpert/gen/bootargs.c#L81-L180) [XNU separators](https://github.com/apple-oss-distributions/xnu/blob/main/pexpert/gen/bootargs.c#L304-L312)

## Review notes

- **Family ownership and link down.** Flow mode registers the family enqueue handler. That handler returns success to BSD even on family overflow. The target's stall result combines retry and stall, so the callback leaves the mbuf owned by the family. The family checks its service generation after the callback, which covers service preceding the committed stall. The target consumes the mbuf for accepted and dropped statuses. The published family includes target drops in its output count. Its drop count covers its own overflow and flushes. The configured packet capacity governs admission to each incoming queue. The primary and shadow lists can combine into a larger backlog. During link down the byte ring is cleared and reset blocks admission under the same lock. Zero capacity, synchronous stop and flush quiesce the old family queue before reopen. A second down before the flush completes is covered by closed admission and the flush. A down after completion sets a new pending reset. The two drop counters describe different queues. The driver's accepted-frame count is measured before USB transfer, and therefore includes frames later cleared from the ring. The target KC's family implementation still requires device qualification. [Apple controller output registration](https://github.com/apple-oss-distributions/IONetworkingFamily/blob/main/IONetworkController.cpp#L888-L937) [Apple queue ownership and accounting](https://github.com/apple-oss-distributions/IONetworkingFamily/blob/main/IOOutputQueue.cpp#L324-L628) [Apple mbuf list accounting](https://github.com/apple-oss-distributions/IONetworkingFamily/blob/main/IOMbufQueue.h#L52-L85)
- **M3 counter path.** The pending-flush check, counter sample and timing transaction run under the flip transaction lock. The gate requires plausible line reads that move on both links and at least two forward frames per link with deltas within one frame, including 32-bit wrap. Equal deltas establish progress. The timing store path separately checks both lines in its write window, and post-switch verification checks line phase and underruns. The boot 60 Hz selection uses the same switch routine. The retained firmware's register behavior requires device evidence.
- **M5 lifetime and memory.** A successful allocation lives with the boot-scoped driver state and is used by the one long-lived panel worker. With allocation failure, capture and publish are skipped and the panel options still apply. The trace reads pages mapped by `premap()`. Ring capture allocates no memory. Formatting and allocating the IORegistry copy happen after a runtime caller is released, on the same worker that will handle the next request. The worst-case publication latency on that worker is unmeasured.
- **0076 sysctl bounds and visibility.** The selected ADT property's scan stops at its first NUL or property size. The merge reserves one byte, rejects oversized or nonprintable tails and exposes the terminated merged line. In the no-tail case the pinned DarwinBoot zeroes its 1024-byte array, rejects input beyond byte 1023, then copies the entire array to the boot-argument structure. Both paths therefore supply a terminated string to `sysctl_io_string()`. `CTLFLAG_RD` and zero writable size make the new OID read-only. The size query reports the full length including NUL, and a short client buffer receives an error. The full line is accessible wherever this OID is readable, including arguments formerly beyond the legacy clip. A direct runtime OID check requires the target kernel. [Pinned DarwinBoot input check](https://github.com/UniXNU/DarwinBoot/blob/8544957e04bdc43e2aac9243764ac16979f15c42/DarwinBootPkg/Driver/DarwinBoot.c#L617-L625) [Pinned DarwinBoot handoff](https://github.com/UniXNU/DarwinBoot/blob/8544957e04bdc43e2aac9243764ac16979f15c42/DarwinBootPkg/Driver/DarwinBoot.c#L746-L757) [Apple sysctl string copy](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_newsysctl.c#L466-L513)
- **Reader fallback and quoting.** The C wrapper falls back only on `ENOENT`. The shell checks the unknown-OID diagnostic under the C locale, which matched the host's Darwin sysctl. Other read errors leave the boot-argument gates inactive. The readers treat quotes and glob metacharacters as data. `piano-rotate` and `piano-rotated` are distinct keys. The normal profiles use plain decimal or comma-list values. Brightness can also start from driver readiness properties.

## Host verification

PianoDpu, PianoDwc3, 0066 merge and clipping, ESP split fixtures, and the USB shell and address helper suites passed. The rotation and brightness helpers built for arm64 macOS, and their host suites passed. The review uses Apple source and timed host models for the queue and panel paths. Live USB, display and sysctl behavior still require target testing.

The final `python3 scripts/ci/self-tests.py` run reported 96 passed, three failed and 16 skipped. The sandbox denies process enumeration for `test-desk-reports.py`, the `hw.memsize` query for `test-ram-m0.sh`, and the loopback bind needed by the fake backup in `test-k273-only.py`. The fake backup failure also reproduced at `0ea7e24d`. The rerun used a detached worktree with scratch beside it inside the clone, so the sensor-pack and private Wi-Fi fixtures could test paths outside the checked-out tree.
