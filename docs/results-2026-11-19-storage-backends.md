# Native Storage Backend Audit

Audit date: 2026-11-19. Static review of the locked device repository at `2438556c77c90c22c7b76e57eb8b40c44b35f1af` and preserved host-side records only. No tablet access, backup, or device write was performed.

The current native root path is UFS-specific. `NativeUfs::startRoot` runs from the root-device personality, reads its root manifest through the UFS transport, selects a GPT partition through `native-ufs-root-part`, and publishes `NativeUfsBlock` windows for the APFS root/SystemOS volumes. The boot argument selects among UFS partition names; it does not select another block provider. The 27.3 layout expects `linux_rootfs` and an associated UFS Data store layout. This device currently has neither partition.

The Data persistence path is also UFS-specific. `NativeRamBlock` waits for `NativeUfs` to finish the root layout before opening its store, then calls the `native_ufs_store_read`, `native_ufs_store_write`, `native_ufs_store_sync`, and GPT-check imports. When that provider is absent, Data remains volatile. The current code does not accept an arbitrary `IOBlockStorageDevice` as its persistent store.

External USB storage is not a ready no-GPT solution. The repository has a gated USB-host path, `PianoXhciHost` A2, and a link configuration including Apple's `IOUSBMassStorageDriver`; the A2 image and host tests were built, but the probe was not run on hardware. That USB stack is brought up behind `PianoUsbHostStack` after the host-controller path, while NativeUfs publishes the initial root windows from its early root-device start. The planned attended H6/A3 acceptance requires a USB device to enumerate and a stick to mount; it has not passed. Even after mount, the existing root selector is UFS-only and NativeRamBlock's persistent store imports are provided by NativeUfs. A USB-root/Data design therefore needs an architectural change that makes the USB block device available before root publication and adds a durable store provider, followed by separate root and Data reboot tests. The current worktree's `out/` contains host test folders only, not the queued A2 boot image; the preserved November 1 worktree has no matching native image or locked k27 source.

Conclusion: do not assume external USB avoids the internal storage dependency. To qualify it, first recover the exact locked k27 tree and matching image inputs, run the no-device A2 diagnostic, then run the attended USB-stick mount test. After that, implement and test early USB root publication and a separate durable Data provider, then prove external APFS root selection and Data persistence across reboot. Until those gates pass, the current storage path requires a designed internal layout; the offline F2FS tool test does not qualify shrinking this tablet's userdata.
