# Retained 27.3 RAM payload audit (2026-11-21)

The manual-reset and firmware-addon images on UbuntuPiano match the image hashes in `outputs/manifests/native-macos-27.3.json`. Both embed the independently linked 26-driver KC (`00f0ba553e16a42021623d9805f6d77ae95ae09d968c761ae1cae4cb6bb06831`). The manual-reset image yielded a readable FAT32 filesystem with 87,713 clusters and the firmware variant had 88,223. Both exceed the pinned FAT driver's 65,525-cluster minimum. Both embed FD `bfc2417a0f9d98d315193986a4dd7668fefc151040b3f29f43accf9b87d94bf1`, which differs from the device-tested isolation FD `d8a41ebb…`.

The extracted ADTs both contain the target root UUID `84581E99-85BE-4957-AC53-2947E887B3E4`. Neither contains the retired UUID. The shared menu has a stale 27.0.1 comment and selects the eight-core XNU entry immediately. Its entries enable `native-ufs-root=1`, `native-ufs-diagnostics=1` and `data-persist=0`. They omit the timer reset, PMIC restart-target and explicit UFS log arguments. The entries do not exercise the UFS register probe alone. Read-only root registration was verified for the linked collection separately from Data and diagnostic write channels.

The manual image's FAT contains a 15,736-byte ADT, a 451,264-byte trust cache, and a 22,200,480-byte seed payload. Their digests are `4e904d90e92e880c3c36f052ccf7b5b8ca6e59099060323d34a6977f1063f3e3`, `002db2e6ee9000c891bad43247bfa9c55ad6d3b2ee62e6c0b9e1965e78926da6`, and `48dbc08d5955a20255268aadc3f79660a62c395a68b358e349bbc3ea8f8b25e0`. The firmware variant preserves a standalone copy of the KC and seed. The prior full verifier log is retained. The new readback inspected the embedded artifacts directly because the verifier's default standalone DTB path was absent.

ADB confirmed the device is on `OS3.0.309.0.WPYCNXM`. Both XNU payloads remain host-only. A probe candidate needs an explicit probe level, a choice of console, and a reviewed firmware path. The desktop candidate still needs its matching UFS root and SystemOS.
